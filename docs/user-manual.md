## 1. 登录与账号

### 1.1 登录

1. 浏览器打开系统地址（开发环境默认 `http://localhost:5173`，生产以管理员告知为准）。
2. 在登录页输入 **用户名** 与 **密码**，点击「登录」。
3. 若提示**首登强制改密**，会跳到「修改密码」页：
   - 旧密码 = 管理员告知的初始密码（如 `Admin@123456`）
   - 新密码：长度 ≥ 8，建议大小写字母 + 数字 + 符号
4. 完成后会自动跳到「综合看板」。

### 1.2 锁定与解锁

- **连续 5 次** 输错密码会被锁定 **15 分钟**（系统默认；管理员可调）。
- 锁定后任由你正确输也进不去，**直接联系系统管理员**到「系统管理 → 用户管理」点 **解锁**，无需等待。

### 1.3 修改密码与退出

- 顶部菜单「账户 → 修改密码」（或地址 `#/system/change-password`）。
- 同样位置有「退出登录」。**长时间未操作会话会过期**，重新登录即可。

### 1.4 我的角色与权限

- 顶部菜单「账户 → 我的信息」可看到：所属部门、当前角色、数据范围（本人 / 本部门 / 全公司）。
- **看不到的菜单 ≠ 系统坏了**，是 RBAC 控制——找管理员申请权限。

## 3. 客户管理

路径：`#/customers`

### 3.1 新建客户

1. 列表页右上角点 **「+ 新建客户」**。
2. 必填项：客户名称、客户类型（个人 / 企业）、级别（A/B/C/D）。
3. 可选：USCC（统一社会信用代码）、地址、联系人占位、备注。
4. 提交后进入客户详情页。**客户名称 / USCC 重复会查重**，可选择「合并」或「使用同名」。

### 3.2 列表搜索

- 顶部搜索栏支持关键字（按名称模糊匹配）。
- 高级筛选：按类型 / 级别 / 创建日期范围。
- **看不到别人创建的客户是预期行为**（数据范围限制）。

### 3.3 详情页 4 个 Tab

进入 `#/customers/:id` 后顶部按钮区有「编辑 / 停用 / 删除（软删）」，下方 4 个 Tab：

| Tab | 你能做什么 |
| --- | --- |
| 基本信息 | 看客户档案、点「编辑」改字段（关键字段变更会写变更记录） |
| 联系人 | + 新增联系人；勾选「设为主联系人」；电话/邮箱自动加密存库 |
| 关联合同 | 该客户名下所有合同列表，点行可跳到合同详情 |
| 变更记录 | 谁、什么时候、改了哪个字段、改前改后 |

### 3.4 客户合并（去重）

发现是同一家公司的两条客户记录，点详情页右上「更多 → 合并到…」，选择 **保留**的客户记录，**被合并**记录下的合同/回款会迁移过去。**该操作不可逆**，请仔细确认。

### 3.5 软删除与禁用

- **删除（软删除）**：仅状态为「未启用 / 无业务」时可删；进入回收站，可还原。
- **停用**：保留客户和历史数据，但不再用于新建合同。

## 4. 合同管理

路径：`#/contracts`

### 4.1 新建合同

1. 列表页右上角 **「+ 新建合同」**。
2. 必填：合同名称、类型（销售 / 采购）、关联客户、金额、签订日、履约开始 / 结束、提醒提前天数（默认 30）。
3. 提交后进入合同详情，**初始状态为「草稿 DRAFT」**。

### 4.2 状态流转（重要）

合同有 5 个状态，**只能按下图迁移**：

```
DRAFT ─────▶ EFFECTIVE ─────▶ COMPLETED
   │             │
   ▼             ▼
TERMINATED   TERMINATED / EXPIRED（系统自动）
```

| 操作 | 入口 | 何时能做 |
| --- | --- | --- |
| 提交履行 | 详情页 → 状态流转 → 「履行中」 | 仅 DRAFT 可点 |
| 完成 | 状态流转 → 「已完成」 | 仅 EFFECTIVE 可点 |
| 终止 | 状态流转 → 「已终止」 | DRAFT / EFFECTIVE 都可 |
| 过期 | 系统每天 08:00 自动 | 履约结束日 +1 自动 EXPIRED |

非法跳转（比如 DRAFT 直接到 COMPLETED）会被系统拒绝并报错 `CT-002 合同状态不合法`。

### 4.3 上传附件（UC-03-05）

合同详情页 → **「附件」Tab**：

- 点 **「上传附件」**按钮选文件。
- 限制：**单文件 ≤ 50MB，单合同最多 20 个**（可由管理员在「系统参数」调整 `contract.attachment.max_count`）。
- 允许扩展名：`pdf / doc / docx / xls / xlsx / ppt / pptx / jpg / jpeg / png / zip / rar / txt`。
- 上传完成后行内有 **「预览/下载」** 与 **「删除」**。
- 失败会弹错误：
  - `FL-003 文件大小超出限制` ← 文件超过 50MB
  - `CT-005 附件类型不允许` ← 扩展名不在白名单
  - `CT-004 附件数量已达上限` ← 该合同已传到上限

### 4.4 备注与变更记录

- **备注 Tab**：销售主管可对合同加备注（销售也能看到），用于沟通要点。
- **时间线 Tab**：自动汇总状态流转、关键字段修改的历史，**不可手工删**。

### 4.5 删除合同（软删）

- 详情页右上「删除」。**仅 DRAFT / TERMINATED / EXPIRED 可删**，履行中的合同需先终止。
- 软删进回收站，**带级联**：附件、变更记录、回款计划、回款记录都跟着进回收站。

## 5. 回款管理

路径：`#/payments`，包含「回款记录」「回款计划」两个子页签。

### 5.1 排回款计划与合计校验

入口：合同详情页 → **「回款计划」Tab**，或 `#/payments` →「回款计划」子页签。

**核心规则（硬校验）**：同一合同所有回款计划的金额合计 **必须恰好等于合同金额**。差额不为 0 时任何保存都会失败，报错 `PM-002`，提示形如：

```
回款计划合计 40000.00 与合同金额 100000.00 不一致，差额 60000.00
```

页面顶部实时显示「合同金额 / 已排合计 / 差额」，差额为 0 时显示「已排满」。

三种录入方式：

1. **批量生成**：输入首期日期（默认合同签订日）、期数（如 12）、频率（月度 / 季度 / 半年 / 年）。系统等额分摊，**末期自动补差**，保证合计等于合同金额。若该合同已有计划需勾选「覆盖」；**存在核销记录时不允许覆盖**（`PM-003`）。
2. **单行录入 / 编辑**（「+ 新增计划」）：填写期数、计划日期、计划金额、提醒天数、备注。保存时按「本次之后该合同的合计」与合同金额比对，差额 ≠ 0 直接拒绝。
3. **批量录入**：一次填多期，可点 **「按合同金额均摊」** 自动生成 12 期并给末期补差；余额不为 0 时「保存」按钮不可点。默认为**覆盖**模式（整体替换该合同原有计划）；取消覆盖则按期数 upsert，未列出的期保留。

其他约束：

- 期数在同一合同内唯一，重复报 `PM-007`。
- 编辑已有计划时，计划金额 **不得小于该期已核销金额**；改金额后系统同步重算该期的「未核销金额」与状态（PENDING / PARTIAL / SETTLED）。
- 已有核销金额的计划 **不能删除**（`PM-003`）。
- 批量导入计划见 [§5.5](#55-excel-批量导入)；收入确认可与回款计划同录，见 [§5.6](#56-收入确认)。

### 5.2 登记实际回款（按期数自动核销）

`#/payments` →「回款记录」子页签右上「+ 新增回款」：

| 字段 | 说明 |
| --- | --- |
| 关联合同 | 必填，远程搜索选择 |
| 期数 | **必填**，下拉只列该合同未结清（非 SETTLED）的计划，显示「第 N 期 · 计划日期 · 待核销 X」 |
| 到账日期 | 客户钱真正到的日子（默认今天） |
| 金额 | 本笔到账金额，必须大于 0 |
| 付款人 | 客户实际打钱的主体（可与客户名不同） |
| 凭证号 | 银行流水号、发票号等（加密存储） |
| 备注 | 可选 |

提交后系统：

1. 写入 `payment_record`（含期数）；
2. 按 **合同 + 期数** 定位唯一计划并加行锁核销（允许**部分核销**）：
   - 本笔金额 ≥ 该期未核销金额 → 该期 **SETTLED**；
   - 本笔金额 < 未核销金额 → 该期 **PARTIAL**，剩余继续待收；
   - 本笔金额超过该期未核销金额 → **只核销到该期为止**，超出部分记入本条回款的「未分配金额」，**不会溢出到下一期**（要覆盖多期请分多笔登记，或用 [§5.4 手工核销](#54-手工核销)）。
3. 月度趋势、账龄、Dashboard 全部刷新。

常见报错：

- 期数未填 → `PM-008`
- 合同 + 期数无对应计划 → `PM-001`（提示「第 N 期回款计划不存在」）
- 该期已结清 → `PM-003`
- 该合同还没有计划 → 先在 [§5.1](#51-排回款计划与合计校验) 排好计划再来登记。

**示例**：3 期 ×10000 元，登记第 2 期 5000 元 → 第 2 期 `PARTIAL`（已核销 5000 / 未核销 5000）；再登记第 2 期 7000 元 → 核销 5000 后该期 `SETTLED`，剩余 2000 记入未分配金额。

### 5.3 红冲（错账纠正）

发现登记错了，**不能直接删**回款记录（违反财务原则），用「红冲」：

1. `#/payments` 列表点错的那行 **「红冲」**。
2. 输入红冲金额（默认全额）和原因。
3. 系统：
   - 生成一条状态为 `RED` 的负数记录；
   - 把原记录改成 `REVERSED`；
   - 撤销在各计划上的核销（计划回到 PENDING / PARTIAL）。

需要 `payment:red` 权限（默认财务有）。

### 5.4 手工核销

如果某笔到账系统自动核销错了对应期，财务可在记录详情点 **「手工核销」**，重新指定要核销到哪几期。需要 `payment:settle` 权限。

### 5.5 Excel 批量导入

进对应页面右上 **「导入」** → 先「下载模板」。要点：

- 单次最多 **2000 行**；表头必须与模板**完全一致**（列名、顺序、列数）。
- 日期支持 `yyyy-MM-dd` 或 Excel 日期格式；金额必须 > 0 且最多 2 位小数。
- 结果页显示成功 N 条 / 失败 M 条 + 每行失败原因（行号从数据行起算）。

**（1）回款记录导入**（`#/payments`，需 `payment:import`）

模板字段（7 列）：`合同编号 / 期数 / 到账日期 / 金额 / 付款方 / 凭证号 / 备注`

- 合同编号不存在 → 该行失败
- 期数为空 → 「期数不能为空」（`PM-008`）；非整数 / ≤0 → 相应提示
- 「合同 + 期数」对应计划不存在或已结清 → `PM-001` / `PM-003`
- **逐行独立**：某行失败不影响其他行，成功的照常入库

**（2）回款计划导入**（`payment:plan_import`）

模板字段（6 列）：`合同编号 / 期数 / 计划日期 / 计划金额 / 提醒天数 / 备注`

- **按合同整组原子**：同一合同的所有行要么全部成功、要么全部失败（不会出现只排了一半）
- 每个合同的计划合计必须等于该合同金额，否则整组失败并报 `PM-002`（含差额）
- 期数在文件内重复 → `PM-007`
- 导入为**覆盖模式**：成功后整体替换该合同原有计划；该合同已有核销记录时整组失败
- 一个文件可包含多个合同的计划，各合同独立判定

### 5.6 收入确认

路径：`#/revenues`（左侧菜单「收入确认」，需 `revenue:list`）。收入确认把合同金额按期间确认为收入，并用「时点平衡」把 **收入 / 实际回款 / 回款计划** 三者绑定校验。

#### 5.6.1 前置条件

录入收入前，该合同必须已排**完整**的回款计划（合计 = 合同金额）：

- 完全没有计划 → `RV-005`「该合同尚未录入有效回款计划」
- 有计划但合计不等于合同金额 → `PM-002`（提示差额，并注明「请先补全回款计划」）

#### 5.6.2 时点平衡公式

对每一笔收入的 **确认日期 T**，必须满足：

```
截至 T 的含税收入合计 = T 之前（含 T）的实际回款 + T 之后（不含 T）的计划待收
```

- **实际回款**：只统计状态为 `NORMAL` 的记录（红冲记录不计入）；
- **计划待收**：取该期「未核销金额」，已核销部分不重复计算。

不成立报 `RV-004`，提示给出等式两边金额与差额。

#### 5.6.3 合同级合计（硬校验）

同一合同所有含税收入合计 **必须恰好等于合同金额**，否则报 `RV-002`：

```
同一合同含税收入合计 90000.00 与合同金额 100000.00 不一致，差额 10000.00
```

> 两条硬校验同时生效，**逐条零散录入通常无法成功**（第一条收入就会因合计不足被拒）。请使用下面的「整批录入」或导入。

#### 5.6.4 整批录入（收入 + 回款计划同录）

`#/revenues` 右上 **「整批录入」**：

1. 选择合同（远程搜索），顶部显示合同金额与已排计划情况。
2. **上半区**填收入明细（可增删行）：确认日期、归属期间、收入类型、含税金额、税率、成本金额。
3. **下半区**填回款计划（可增删行），可点 **「按合同金额均摊」** 快速生成 12 期并补差末期。
4. 右侧「校验预演」实时显示：合同金额、收入合计与差额、已排计划与差额、时点平衡差额。
5. 仅当 **收入差额 = 0** 且 **计划差额 = 0** 时「保存」可点。
6. 保存为**单事务**：先写计划 → 再校验 → 再写收入；任一步失败整批回滚，不会留下半套数据。

金额自动派生：税额 = 含税金额 × 税率（四舍五入 2 位），不含税金额 = 含税 − 税额，毛利 = 不含税 − 成本。

#### 5.6.5 收入列表

`#/revenues` 列表支持按合同、收入归属期间（`YYYY-MM`）、收入类型、确认日期范围筛选；行内可编辑（`revenue:update`）/ 删除（`revenue:delete`）。修改或删除同样会重跑合同级校验，校验不过会被拒绝。

列表顶部可按合同查看「收入合计 vs 合同金额」汇总（`GET /revenues/summary/{contractId}`）。

#### 5.6.6 收入明细导入（需 `revenue:import`）

模板字段（9 列）：`合同编号 / 收入归属期间 / 确认日期 / 收入类型 / 含税金额 / 税率 / 成本金额 / 单据号 / 备注`

- **按合同整组原子**：同一合同的多行同成功、同失败
- 收入归属期间格式 `YYYY-MM` 且不得晚于当前月，否则 `RV-003`
- 收入类型可填 `商品 / 服务 / 其他` 或 `GOODS / SERVICE / OTHER`，留空默认「服务」
- 税率填 0~1 之间的小数（如 `0.06` 表示 6%），最多 4 位小数；成本金额可留空（按 0 处理）
- 校验顺序：合同存在 → 计划完整（`RV-005` / `PM-002`）→ 时点平衡（`RV-004`）→ 合同合计（`RV-002`）

## 6. 报表与账龄

### 6.1 账龄分析

路径：`#/payments/aging`

四桶展示当前未结清金额：

| 桶 | 含义 |
| --- | --- |
| UNDUE | 未到期 |
| 0-30 | 已逾期 0-30 天 |
| 31-90 | 已逾期 31-90 天 |
| OVER_90 | 逾期超 90 天 |

点任一桶的「钻取」可看明细——具体哪些计划在这个桶里。

### 6.2 报表中心

路径：`#/reports`，常用报表：

| 报表 | 内容 | 导出格式 |
| --- | --- | --- |
| 月度趋势 | 近 N 月合同 / 回款 / 应收金额折线 | Excel |
| TOP 客户 | 按已回款 / 待回款 / 合同额 TOP N | Excel |
| 我的待办 | 个人未完成项（应跟进合同、待登记回款等） | — |

需要 `report:export` 权限才能导出。

## 7. 通知中心

路径：`#/notifications`，顶部铃铛图标显示未读数量。

### 7.1 站内信场景

| 场景 | 何时触发 | 默认接收人 |
| --- | --- | --- |
| `CONTRACT_DUE` | 合同到期前 30 天（每天 09:00） | 合同负责人 + 部门主管 |
| `PAYMENT_DUE_SOON` | 计划日前 7 天（每天 09:30） | 合同负责人 |
| `PAYMENT_OVERDUE` | 已逾期，每 3 天重复 | 合同负责人 + 财务 |

提前天数与重复周期可由管理员在 [系统参数](./admin-manual.md#42-参数说明) 调整。

### 7.2 操作

- 点单条 → 标记已读。
- 「全部已读」一键清未读。
- 「归档」把不再需要的旧通知折叠。
- 「设置」：可关闭某些场景的提醒（自己关的，不影响别人）。

## 8. 软删除与回收站

### 8.1 删除策略

CRMS 默认所有删除都是 **软删除**：

| 业务 | 谁能软删 | 进哪种回收站 |
| --- | --- | --- |
| 客户 | 销售（自己的）/ 系统管理员 | `CUSTOMER` |
| 合同 | 销售（DRAFT）/ 系统管理员 | `CONTRACT`（带级联） |
| 回款记录 | 系统管理员 | `PAYMENT_RECORD`（不推荐，请用红冲） |

### 8.2 还原

- 业务用户**没有回收站权限**——找系统管理员到 `#/system/recycle` 还原。
- 还原后的记录回到原列表，状态保持原样。

### 8.3 硬删除（仅超管）

**不可逆**操作，仅 R05 系统管理员可做，且需要：
- 二次密码确认；
- 写入 `hard_delete_log`，含操作人、时间、原因、原快照。

普通用户**永远用不到**这个；误操作请走「还原」。

## 9. 常见错误码速查

按业务前缀分类（完整见 [DSS §6.5](./dss.md)）：

| 错误码 | 含义 | 你应该 |
| --- | --- | --- |
| `AUTH-401` | 未登录 / Token 过期 | 重新登录 |
| `AUTH-403` | 无权限 | 找管理员申请权限点 |
| `VAL-400` | 参数校验失败 | 看错误信息里说哪个字段 |
| `CU-001` | 客户不存在 | 客户已被删或 ID 错 |
| `CU-002` | USCC 已存在 | 走客户合并 |
| `CT-001` | 合同不存在 | 同上，或被删 |
| `CT-002` | 合同状态不合法 | 看 §4.2 状态机 |
| `CT-004` | 附件数量已达上限 | 删除旧附件或找管理员调系统参数 |
| `CT-005` | 附件类型不允许 | 改用白名单内的扩展名 |
| `PM-001` | 回款计划不存在 | 检查「合同 + 期数」是否已排计划（见 [§5.1](#51-排回款计划与合计校验)） |
| `PM-002` | 回款计划合计与合同金额不一致 | 调整计划金额，使合计**恰好等于**合同金额 |
| `PM-003` | 回款计划已结清 / 已有核销 | 该期已 SETTLED 或有核销金额，不可改金额、删除或覆盖 |
| `PM-007` | 回款计划期数重复 | 同一合同同一期数只能有一条计划 |
| `PM-008` | 实际回款未指定期数 | 登记回款 / 导入回款时必须填期数 |
| `RV-001` | 收入明细不存在 | ID 错或已被删 |
| `RV-002` | 收入合计与合同金额不一致 | 同一合同含税收入合计必须恰好等于合同金额 |
| `RV-003` | 收入归属期间非法 | 用 `YYYY-MM`，且不得晚于当前月 |
| `RV-004` | 收入确认时点不平衡 | 按 [§5.6.2](#562-时点平衡公式) 公式调整确认日期或金额 |
| `RV-005` | 该合同尚未录入有效回款计划 | 先排完整回款计划再确认收入 |
| `FL-002` | 文件上传失败 | 网络 / 存储问题，重试或找运维 |
| `FL-003` | 文件大小超出限制 | 单文件 ≤ 50MB |
| `SY-001` | 系统参数不存在 | 联系管理员检查参数表 |
| `SY-501` | 硬删除被拒 | 你没有该权限 |
| `SYS-500` | 系统错误 | 复制 traceId 给运维（在错误提示里） |

每条错误响应都带 `traceId`，**报问题时连同 traceId 一起发**，运维可在日志里精确定位。

## 10. 三个最常见的"我以为系统坏了"

| 现象 | 实际原因 |
| --- | --- |
| 菜单点了 404 | 你的角色没有该路由的权限点 |
| 列表是空的，但同事说他能看到 | 数据范围（SELF）限制：你只看到自己创建的 |
| 改了系统参数没生效 | 只有部分参数热生效（如附件上限、提醒天数）；个别需重启服务，问管理员 |
