# 回款计划录入 / 实际回款期数核销 / 收入确认模块 实施计划

## 一、Summary（目标概述）

在现有 CRM（合同回款管理系统）上新增/增强三块能力：

1. **回款计划**：支持单行录入与批量导入，并新增「同一合同回款计划合计必须恰好等于合同金额」的硬校验。
2. **实际回款**：新增「期数」字段，登记时按「合同 + 期数」自动定位回款计划并核销（期数必填，允许部分核销）。
3. **收入确认管理**：新增独立模块，支持单行录入、批量导入收入明细，字段预设，并叠加「同一合同收入合计 ≤ 合同金额」校验。

不改动既有客户、合同主流程；所有改动遵循项目现有的 Controller → Service → Mapper、EasyExcel 导入、`ImportResultVO` 回执、`SaCheckPermission` 权限点、Flyway 迁移、Vue3 + Element Plus 页面模式。

## 三、Assumptions & Decisions（关键决策）

### 已由用户确认

| 编号 | 决策 |
|---|---|
| D1 | **回款计划合计为硬校验**：新增/编辑/批量录入/导入后，「该合同所有未删除计划金额合计」必须**恰好等于** `contract.amount`，否则拒绝保存。 |
| D2 | **实际回款期数必填**，按「合同 + 期数」定位唯一计划并核销；**允许部分核销**（回款金额 < 该期待核销额时，差额留在 `payment_record.unallocated_amount`，不跨期分配）。 |
| D3 | **收入确认叠加合同金额校验**：自身字段校验 + 「同一合同收入明细合计 ≤ 合同金额」。 |

### 由现状推导、需要落实的决策

| 编号 | 决策 | 理由 |
|---|---|---|
| D4 | 删除回款计划时**不做**合计校验（允许暂时产生差额），页面用红色「差额」标签提示 | 硬校验若覆盖删除，将无法删除任何期次，业务不可用；录入类操作仍严格拦截 |
| D5 | 新增「**批量录入**」入口（同一合同多期一次性提交，事务内校验合计后落库） | 硬校验下逐行录入几乎不可用（除非刚好补足尾差），必须提供整批提交能力 |
| D6 | 回款计划 Excel 导入按「**合同整组原子处理**」：先按合同编号分组，组内期数不重复、组内合计 == 合同金额、且该合同现有计划均无核销记录，才覆盖写入；任一条件不满足则**整组失败**并把错误回写到该组每一行 | 硬校验是合同级约束，无法逐行独立通过；避免半套计划入库 |
| D7 | 回款计划导入为**覆盖模式**（软删该合同原有计划后写入）；若该合同已有计划存在 `settled_amount > 0`，整组拒绝并提示改用单行调整 | 避免销毁已核销数据 |
| D8 | `payment_record.period_no` 在 DB 层允许 `NULL`（兼容历史数据），业务层（DTO `@NotNull`、导入必填）强制非空 | 纯 `ADD COLUMN NOT NULL` 会让历史空表之外的数据无法兼容；业务校验即可满足需求 |
| D9 | `CreateRecordDTO` 中移除 `targetPlanIds`，改为 `periodNo`；`ManualSettleDTO.planIds` 保持不变（手工核销接口仍支持多期） | 期数必填后，登记回款不再需要手工选期；手工核销是独立能力 |
| D10 | 收入明细预设字段见下（用户授权自行预设），金额采用「含税金额 + 税率」推导「税额 / 不含税金额 / 毛利」 | 兼顾财务口径与录入成本 |

**收入明细表 `revenue_record` 预设字段**

| 字段 | 类型 | 说明 |
|---|---|---|

| `recognize_date` | DATE NOT NULL | 收入确认日期 |

/** 硬校验：该合同未删除计划合计必须恰好等于合同金额（excludeId 用于编辑时排除自身）。 */
private void assertTotalEqualsContract(Long contractId, Long excludeId, String action) {
    Contract c = contractMapper.selectById(contractId);
    if (c == null) throw new BizException(ErrorCode.CT_NOT_FOUND);
    BigDecimal others = planMapper.sumPlanAmountExcluding(contractId, excludeId);
    BigDecimal amount = resolveIncomingAmount();   // 由调用方传入本次金额
    BigDecimal total = others.add(amount);
    if (total.compareTo(c.getAmount()) != 0) {
        BigDecimal diff = c.getAmount().subtract(total);
        throw new BizException(ErrorCode.PM_PLAN_AMOUNT_MISMATCH,
            "回款计划合计 " + total + " 与合同金额 " + c.getAmount()
            + " 不一致，差额 " + diff);
    }
}
```

实现方式：把「新增/编辑金额」作为参数传入（`BigDecimal incoming`）；新建时 `excludeId=null`，编辑时 `excludeId=id`。

/** 按「合同 + 期数」定位计划并核销；金额不足时部分核销，剩余留在 record.unallocated_amount。 */
BigDecimal settleByPeriod(PaymentRecord record, Integer periodNo);
```

实现（复用现有事务与锁约定，`propagation = REQUIRED`）：
1. `recordMapper.selectForUpdate(record.getId())` → 不存在 / 已红冲 → 原有异常；
2. `planMapper.selectByContractAndPeriodForUpdate(contractId, periodNo)` → `null` 抛 `BizException(PM_PLAN_NOT_FOUND, "第 " + periodNo + " 期回款计划不存在")`；
3. `"SETTLED".equals(plan.getStatus())` → 抛 `BizException(PM_PLAN_SETTLED, "第 X 期已结清")`；
4. `portion = min(remaining, plan.getUnsettledAmount())`，若 `portion.signum() <= 0` 则不写核销记录，仅回写 `unallocated_amount`；
5. 写 `payment_settlement`（`settle_type = "AUTO"`）、更新 plan（`PARTIAL`/`SETTLED`）、乐观锁失败抛 `SYS_ERROR`；
6. 回写 `payment_record.unallocated_amount = remaining - portion`。

- 改调 `settlementService.settleByPeriod(r, dto.getPeriodNo())`；

**金额派生与校验（`RevenueRecordServiceImpl` 私有方法 `applyDerived`）**
- `taxRate` 为空 → 0；范围 `[0,1]`、最多 4 位小数 → 否则 `BizException(VALIDATION_ERROR, "税率必须在 0~1 之间且最多 4 位小数")`；
- `taxAmount = amount.multiply(taxRate).setScale(2, HALF_UP)`；
- `netAmount = amount.subtract(taxAmount)`；
- `costAmount` 空 → `ZERO`，`<0` 拒绝；
- `grossProfit = netAmount.subtract(costAmount)`；
- `periodMonth` 不得晚于当前月 → 否则 `BizException(VALIDATION_ERROR, "收入归属期间不能晚于当前月")`。

**同合同合计校验（D3）**
- `create`：`existingSum = mapper.sumAmountByContract(contractId, null)`；`existingSum + amount > contract.amount` → `BizException(RV_AMOUNT_EXCEED, "收入合计 X 已超出合同金额 Y")`；
- `update`：`sumAmountByContract(contractId, id)` 排除自身后重算；
- `remove`：不校验（与 D4 同口径）。

**收入导入** `RevenueImportServiceImpl`
- `HEADERS = {"合同编号","收入归属期间","确认日期","收入类型","含税金额","税率","成本金额","单据号","备注"}`
- 逐行校验（复用 `ExcelImportHelper`）：合同编号非空且存在 → 期间格式 → 确认日期（`parseDateFlexible`）→ 收入类型枚举（中文/英文双写兼容：`商品/服务/其他` ↔ `GOODS/SERVICE/OTHER`）→ 金额（`parseAmount`）→ 税率（字符串转 `BigDecimal`，0~1、≤4 位小数）→ 成本（≥0、≤2 位）→ 单据号长度 + 文件内去重 → 备注长度；
- 逐行调用 `revenueRecordService.create(dto)`，`RV_AMOUNT_EXCEED` 自然按行回写错误。

### 5.2 运行态验证（沿用当前已启动的环境：后端 8080 / 前端 5173）

   - 合同金额 100000：单行录入 40000 → 应返回 `PM-002`，提示差额 60000；
